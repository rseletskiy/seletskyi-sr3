## 1. Перевантаження та шаблон функції максимуму

У просторі імен `overloaded` визначено чотири числові перевантаження `maximum`: для `int/int`, `double/double`, `int/double` і `double/int`. Компілятор вибирає відповідну функцію за типами аргументів.

Шаблон `maximum<T, U>` описує алгоритм один раз для двох типів. Тип результату визначає `std::common_type_t<T, U>`. Наприклад, `maximum(3, 3.5)` повертає `double` зі значенням `3.5`.

Виправлено помилку змішаного порівняння цілих чисел: раніше `maximum(-1, 2U)` спочатку перетворював `-1` на беззнаковий тип. На перевіреній платформі це давало `4294967295`, яке помилково ставало максимумом.

Тепер для цілих типів із різною знаковістю спочатку перевіряється від'ємність знакового аргументу. Від'ємне число завжди менше за беззнакове. Якщо знакове число невід'ємне, порівняння виконується після безпечного перетворення цього числа на відповідний беззнаковий тип. Тип результату збережено.

Обидва виклики `maximum(-1, 2U)` та `maximum(2U, -1)` повертають `2`. Перевірки в `tests.cpp` охоплюють обидва порядки аргументів, нуль, діапазон малих значень і граничні значення цілих типів.

## 2. Мінімальний елемент масиву

Функція `minimumElement<T>(const T* values, std::size_t size)` проходить масив і зберігає адресу найменшого елемента. Для порівняння використовується `operator<`.

Для масиву `{5, -2, 9, 0}` результат дорівнює `-2`, для `{3.5, -1.25, 2.0}` результат дорівнює `-1.25`.

Часова складність становить `O(n)`, додаткова пам'ять становить `O(1)`. Функція повертає посилання на елемент вихідного масиву, тому масив має існувати протягом використання результату. Порожній масив або нульовий вказівник спричиняє `std::invalid_argument`.

## 3. Клас Tovar і порівняння об'єктів

Клас `Tovar` містить назву та ціну. Оператор `operator<` порівнює товари за ціною. Оператор `operator<<` виводить назву, ціну та позначення валюти.

Шаблон `maximumElement` використовує цей оператор без окремої реалізації для товарів. Серед товарів `Book (250)`, `Pen (30)` та `Notebook (120)` він знаходить `Book` за ціною `250`.

Якщо ціни однакові, алгоритм залишає перший знайдений товар. Конструктор відхиляє від'ємну та нескінченну ціну, а також `NaN`.

## 4. Шаблон класу Array

`Array<T>` володіє динамічним масивом `T*` та зберігає його розмір. Конструктор виділяє пам'ять через `new T[size]{}`, а метод `output` виводить усі елементи.

Інтерфейс також містить `size()` і дві версії `operator[]`: для змінного та сталого об'єкта. Вихід за межі масиву спричиняє `std::out_of_range`.

Визначення методів винесені за межі оголошення класу, але залишені в заголовковому файлі. Вони мають бути доступні компілятору під час інстанціювання шаблону.

У програмі створюються `Array<int>` і `Array<double>`; у тестах також перевірено `Array<Tovar>`. Поточна реалізація потребує типу з доступним конструктором без аргументів і копіювальним присвоюванням. Для виклику `output` тип має підтримувати `operator<<`.

## 5. Копіювання та звільнення пам'яті

Конструктор копіювання виділяє окремий масив і копіює в нього елементи. Копія не використовує пам'ять оригіналу. Деструктор звільняє пам'ять через `delete[]`.

Оскільки клас володіє ресурсом, реалізовано також оператор копіювального присвоювання за правилом трьох. Він створює тимчасову копію та обмінює її дані з поточним об'єктом. Самоприсвоювання враховано.

Під час копіювання тимчасовий `std::unique_ptr<T[]>` звільнить новий масив, якщо копіювання елемента завершиться винятком. Невдале присвоювання залишає цільовий об'єкт без змін.

Демонстрація:

- Початковий масив: `10 20 30`.
- Після створення копії та зміни оригіналу: оригінал `99 20 30`, копія `10 20 30`.
- Після присвоювання та наступної зміни оригіналу присвоєна копія зберігає `99 20 30`.

## 6. Спеціалізація для рядків

Для `maximum<std::string, std::string>` визначено явну спеціалізацію. У цьому прикладі максимумом рядків вважається довший рядок. За однакової довжини вибирається лексикографічно більший.

Виклик `maximum(std::string("zoo"), std::string("apple"))` повертає `"apple"`. Спеціалізація працює саме зі `std::string`; рядкові літерали потрібно спочатку перетворити на цей тип.

## 7. Перевантаження та спеціалізація

Перевантаження створює окрему функцію з тією самою назвою та іншим набором параметрів. Компілятор розглядає перевантаження під час вибору функції.

Явна спеціалізація задає окрему реалізацію вже оголошеного шаблону для конкретних аргументів типу. Вона використовується після вибору відповідного основного шаблону. Часткова спеціалізація шаблонів функцій не дозволена; для такого розділення поведінки можна використати перевантаження.

Власний приклад використовує два правила порівняння рядків:

| Виклик | Механізм | Правило | Результат для `"zoo"` і `"apple"` |
| --- | --- | --- | --- |
| `overloaded::maximum(a, b)` | Звичайне перевантаження для `std::string` | Лексикографічне порівняння | `zoo` |
| `maximum(a, b)` | Явна спеціалізація шаблону | Довжина, потім лексикографічне порівняння | `apple` |

Різні простори імен дозволяють явно вибрати потрібний приклад. Правила порівняння задано навмисно, щоб продемонструвати різну реалізацію для того самого типу.

## 8. Один алгоритм для стандартного та власного типів

У `main.cpp` один шаблон `maximumElement` викликається для масиву `int` і масиву `Tovar`.

Для `int` порівняння є вбудованою операцією. Для `Tovar` викликається визначений у класі `operator<`. Сам алгоритм в обох випадках має однаковий код.

Результати: `9` для числового масиву та `Book (250.00 UAH)` для товарів.

## 9. Пояснення помилки шаблону за допомогою ШІ

### Запит

> Поясни помилку компіляції C++17. Шаблон maximumElement(const T* values, std::size_t size) порівнює елементи виразом *result < values[i]. Я передаю масив об'єктів struct WithoutComparison { int value; }. Компілятор повідомляє: no match for operator<, operand types are const WithoutComparison and const WithoutComparison. Якої операції бракує, чому помилка з'являється під час інстанціювання шаблону та як виправити клас без зміни алгоритму?

### Отримане пояснення

Шаблон вимагає, щоб два сталі об'єкти типу `T` можна було порівняти через `<`. Наявність числового поля `value` не створює для класу оператор порівняння автоматично.

Під час інстанціювання `maximumElement<WithoutComparison>` компілятор перевіряє вираз із конкретним типом і не знаходить відповідного оператора. У клас потрібно додати:

```cpp
bool operator<(const WithoutComparison& other) const {
    return value < other.value;
}
```

Метод є сталим, оскільки алгоритм отримує доступ до елементів через `const T*`. Алгоритм при цьому змінювати не потрібно.

### Перевірка пояснення

У `main.cpp` передбачено режим, який вмикає клас без оператора та помилковий виклик:

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic -DSHOW_TEMPLATE_ERROR main.cpp -o template-error
```

Компіляція з цим прапорцем очікувано завершується помилкою. GCC 14.2 вивів:

```text
error: no match for ‘operator<’ (operand types are ‘const WithoutComparison’ and ‘const WithoutComparison’)
```

Для перевірки виправлення у тимчасову копію класу було додано наведений оператор. З тим самим прапорцем програма скомпілювалася та повернула `2` для масиву `{{1}, {2}}`. Звичайний запуск без прапорця теж успішний; клас `Tovar` демонструє робочий варіант із власним оператором порівняння.

Отже, пояснення підтверджене як відтворенням помилки, так і успішною компіляцією виправленого прикладу.

## Збирання та запуск

Файли `main.cpp` і `tests.cpp` містять окремі функції `main`, тому їх потрібно збирати окремо.

Linux або термінал GitHub Codespaces із встановленим GCC:

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic -Werror main.cpp -o sr3
./sr3
g++ -std=c++17 -Wall -Wextra -Wpedantic -Werror tests.cpp -o tests
./tests
```

Windows PowerShell із встановленим MinGW-w64 і доступною командою `g++`:

```powershell
g++ -std=c++17 -Wall -Wextra -Wpedantic -Werror main.cpp -o sr3.exe
.\sr3.exe
g++ -std=c++17 -Wall -Wextra -Wpedantic -Werror tests.cpp -o tests.exe
.\tests.exe
```
